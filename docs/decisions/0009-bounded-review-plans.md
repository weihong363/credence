# 0009 — Persist one bounded plan and reserve final synthesis capacity

Status: locally implemented and tested, 2026-10-22. Live full-review acceptance subsequently passed after explicit owner authorization; see p1-full-review-live-evidence.json. Refines ADR 0008 following the owner's request to address same-task three-service completion.

A successful baseline used seven model requests: three purchase choices, two providers, a finish choice and synthesis. Two legitimate provider corrections required nine, beyond the eight-request budget. Change coordination rather than increase that bound or the owner's credit.

All new missions use one validated procurement plan. The model chooses up to five unique registry-backed capability/version entries with concise reasons; it cannot supply prices. Plan validation, account/task/per-purchase preflight and immutable persistence precede purchases. Every actual purchase still gets a fresh authoritative quote and atomic policy/reservation checks. Planning JSON/schema may be repaired once before execution; a failed required service ends a full review rather than silently weakening its scope. No legacy decision-loop path remains.

Persist a task acceptance profile: `scoped` for limited objectives and `full-review` for exactly inventory, architecture and independent risk review. The CLI selects full-review explicitly; programmatic callers select a profile (default scoped). Profile changes are prohibited. Full-review completes only with three matching accepted purchases on the same task. Synthesis for either profile must cite every accepted delivery. Returned results and local status expose the profile; historical scoped COMPLETED tasks are not retroactively claimed as full reviews.

Migration 5 adds immutable procurement plans, task profile/model phase and append-only model request purpose. It retains existing IDs, reports, ledger rows and request counts. Historical requests are labeled LEGACY; no previous task is reopened. Reopened execution loads the saved plan and skips accepted purchases, fencing stale workers as before. Version-one and version-four migration tests cover history preservation.

The durable eight-call limit remains. Planning/provider calls may consume at most seven, preserving one synthesis attempt. All HTTP retries count. Preflight also rejects plans that cannot afford the minimum remaining providers plus synthesis. This is not a guarantee every possible retry combination succeeds: exhausted budgets, missing evidence, network failures and expired deadlines still fail visibly. A provider's malformed JSON/schema or invalid selection records a rejected empty marker and may use its existing single correction; it never creates a successful delivery or charge by substitution.

Normal full review now uses four requests (plan, architecture, risk, synthesis), two provider corrections use six, and two further transient HTTP retries fit eight. Offline tests use production adapters/verifier/SQLite with mocked HTTP. Crash/replay, missing plan entries, insufficient policy, required-provider rejection, missing final coverage, request reservation and malformed outputs are tested. The initial offline change authorized no fresh credit. The owner subsequently explicitly authorized a separate 1,500-unit account and one live verification; the resulting full-review success used five model requests and 750 units. No payment or Render deployment occurred.
