# ADR 0016: owner-controlled mission entry with durable request identity and fenced recovery

Accepted 2026-10-23 for the next P3.4 slice.

Add owner-only POST /api/missions, GET /api/mission-requests/:key and POST /api/tasks/:id/resume. Use existing cookie/CSRF or Bearer authentication and strict body schemas. Source must be a public GitHub repository pinned to a commit; the server fixes the full-review objective, USD 10.00 task budget, eight-call cap and five-minute deadline. Available account allowance, policy and registry prices are validated before the task/request transaction commits. No caller-supplied price, model credential or PayPal authority is accepted.

Schema v8 adds append-only start/resume request records and operational mission leases, without rebuilding or rewriting existing economic tables. A repeated start key returns the same task; a changed payload conflicts. Live leases serialize HTTP execution across database connections, with a 90-second lease renewed every ten seconds and guard checks around remote calls/source persistence. Financial reservation, invocation and accepted-charge uniqueness remain enforced by existing transactions and operation keys. Explicit recovery reuses the same task/plan/invocations, deadline and persisted model-call budget. Terminal tasks return their saved result without another model call. Server restart does not automatically launch tasks; the owner resumes after lease expiry. Native graceful shutdown fences execution and drains it before closing the database; forced shutdown leaves recoverable persisted intent.

The browser requires explicit model/source/spending authorization. It saves only the pending request UUID, account ID and public repository revision in sessionStorage before submitting, so an interrupted response can be looked up/retried without creating another task. No owner token, CSRF/session credential, source contents or payment key is stored there. Restore performs a read-only lookup, never an automatic start/resume. Successful lookup/ack clears the journal. Model secrets use the existing server-only LLM_BASE_URL/LLM_MODEL/LLM_API_KEY; missing/invalid configuration disables execution but leaves inspection/settlement usable.

The default CLI remains available. It cannot resume a currently leased HTTP task. Cloud deployment stays single-instance with its existing disk; no worker/queue/service dependency is introduced. Unit/integration tests cover replay, separate-connection exclusion, rollback, expired-worker fencing, deadlines, no-spend rejection and v7 history preservation. This local acceptance does not establish the five consecutive live UI procurement/payment gate.
